# 路由式用户问题处理工作流设计

## 目标与范围

为公开医疗资料 RAG 增加四个可复用的用户问题处理节点：问题重写、复杂问题分解、假设性回答（HyDE）和抽象问题（step-back）。由模型路由器从四种处理和原问题直通中选择**恰好一种**，不让每个问题都经过四个转换。发布独立的可选问答工作流 `medical-answer-expanded`，保留已有 `medical-answer`、`medical-search` 及 `/answers` 默认行为。新流程从现有工作流运行接口调用，并在节点库及编辑器中可见。

四个节点处理用户的原始问题，不检查检索结果。抽象问题分支被选中时生成更上位的问题，不以检索失败为触发条件。该流程不改变资料上传、索引、默认检索和默认问答流程。

## 方案比较与选择

1. **模型路由（选用）**：Qwen 对原问题做一次结构化分类，返回 `direct`、`rewrite`、`decompose`、`hyde`、`stepback` 中唯一一种。能按语义选择处理策略，直通时不再额外改写；代价是一次路由模型调用和小范围分支汇合机制。
2. 纯规则路由：延迟低且无需路由模型调用，但措辞多样时容易误判。
3. 规则加模型路由：先匹配简单规则，再由模型处理其余问题；节省部分调用，却增加规则边界与维护成本。

现有引擎按确定的拓扑顺序执行 DAG。新工作流图包含四个候选分支，但只有选中的处理节点实际调用 Qwen；未选分支留下 `skipped` 追踪，不生成检索变体。

## 节点接口与职责

`question.router` 接受 `question: string` 和 `provider: string`，通过现有 Qwen 传输接口输出 `route: string`，只允许五种固定值。清晰、单一且不需扩展的问题可选择 `direct`；多子目标倾向 `decompose`，含混表达倾向 `rewrite`，需要语义式模拟文本的检索倾向 `hyde`，过于具体且需要上位概念辅助检索的提问倾向 `stepback`。分类输出非法、为空或不属于固定枚举时按 `direct` 处理，不尝试猜测其他路径。

四个新处理节点接受 `question: string`、`provider: string` 和 `route: string`，只有自己的 route 被选中时才使用 Qwen；节点提示词将用户输入视为数据，不执行用户输入中要求改变节点职责的指令。

| 节点类型 | 选中时的内容 | 职责 |
| --- | --- | --- |
| `question.rewrite` | 一个明确的问题 | 保留原意，补全检索所需的明确措辞；不引入医学事实。 |
| `question.decompose` | 最多 3 个子问题 | 把确有多个子目标的问题拆为独立可检索子问题。 |
| `question.hyde` | 一段模拟回答 | 生成简短、明确标记为未验证的模拟回答文本，仅作向量查询。 |
| `question.stepback` | 一个抽象问题 | 生成一个更上位、但仍与原问题主题相关的问题。 |

路由和转换输出要求为结构化 JSON：路由形如 `{"route":"decompose"}`；重写／抽象问题形如 `{"question":"..."}`；分解形如 `{"questions":["...", "..."]}`；HyDE 形如 `{"hypothetical":"..."}`。解析后校验类型、非空、长度和数量：每条转换问题最多 256 字符、模拟回答最多 600 字符、子问题最多 3 条，超出上限视为无效而非截断。选中的转换格式无效或内容为空时退回原问题。未选节点不调用模型，输出 `active=false` 的占位 `query_variant`，追踪状态为 `skipped`；选中节点输出 `active=true` 的 `query_variant`。真实模型调用失败（包括认证、限流和服务不可用）沿用现有安全错误路径，令新工作流失败，不把它冒充证据不足。密钥不进入工作流 JSON、追踪记录或用户响应。

新增 `question.select` 汇合节点接受原问题、路由值和四个 `query_variant`，仅提取被选中的有效变体，产出 `query_plan`；`direct` 只保留原问题。原问题必定排在第一位；按首尾空白剔除后的文本去重，同一文本在问题与模拟回答之间也只检索一次。因每次只选一条分支，最多形成原问题加 3 条子问题，或原问题加 1 条模拟回答。模拟回答只标记为向量查询，不作为事实证据。新增 `retrieval.expanded` 节点接受 `query_plan`，对每条问题类文本执行向量和 BM25 检索，对模拟回答只执行向量检索；每次检索的候选数默认沿用 `candidate_k=20`，跨查询按现有 RRF 默认 `k=60` 以块 ID 去重融合，输出 `evidence_list`。节点不把模拟回答文本塞入 Evidence。

现有引擎不会保存 `skipped` 节点的输出，也会跳过输入缺失的汇合节点。为实现可见的路由分支，只对**节点显式返回**的 `skipped` 结果保存其占位输出，供 `question.select` 消费；因缺失输入或证据门控而由引擎跳过的节点仍无输出。四个占位端口始终连通，保持已有必填端口和工作流校验语义；旧流程不受该机制影响。新增 `query_variant`、`query_plan` 端口类型只在相关节点间传递，不改变已有节点接口。

## 工作流数据流与安全边界

`query.input` 的原问题和 provider 进入 `question.router`；路由值连至四个转换节点。原问题、路由值及四个变体进入 `question.select`，再由 `retrieval.expanded` 产出候选证据。候选证据进入既有 `retrieval.rerank`，其 question 端口仍使用原问题，top_k 仍来自 `query.input`。其后保持 `evidence.gate` → `generation.llm` → `citation.validate` → `answer.output`，回答生成的 question 端口仍使用原问题。既有问答安全校验要求 gate 的证据来自 rerank、生成证据来自 gate、答案来自引用校验；新图须满足这些约束。

选中分支的转换结果只能扩大候选召回，不能成为回答内容、引用来源或医学事实。证据为空或不满足门槛时继续使用现有固定拒答；有效引用必须指向本次检索到的真实资料块。发布 `workflows/medical-answer-expanded.v1.json`，不替换或改写现有默认工作流。通过 `/workflows/medical-answer-expanded/runs` 调用；现有 `/answers` 和 `/search` 不切换工作流。

## 验证与边界

自动化测试用伪 Qwen 传输和内存检索对象，不调用收费 API。覆盖 `direct` 和四个转换路由的正常结构化输出、非法路由回退、未选节点标记跳过且不调用模型、选中节点非法 JSON／空值／超长文本回退、子问题上限与模型调用失败；覆盖分支占位汇合、原问题优先和去重、HyDE 只调用向量检索、跨查询块 ID 融合，以及新图的发布校验和端到端运行。回归测试确认旧图输出、拒答、引用校验及 `/answers` 默认绑定不变。按项目开发命令运行 Python 测试与静态检查；涉及前端节点库展示时运行前端测试、lint 和 build。真实 Qwen/Milvus 表现另以受控环境验证，自动化通过不等于医学正确性已验证。

每次运行先发生 1 次路由模型调用，非直通路径至多再发生 1 次转换模型调用，证据通过门控后才发生回答模型调用。检索至多尝试 4 条问题类文本，或 1 条原问题和 1 条 HyDE 文本；当前同步模型传输及顺序 DAG 执行会增加延迟和调用量。这是独立可选流程的明确代价，不在本次增加通用条件调度、并发执行、新页面或自动切换默认流程。
