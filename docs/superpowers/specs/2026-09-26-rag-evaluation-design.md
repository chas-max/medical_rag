# RAG 离线评估设计

## 目标与范围

为现有公开医疗资料 RAG 后端增加按需运行的离线评估，覆盖检索 Precision@k、Recall@k、F1@k、MAP@k、MRR@k，以及由模型评审的 faithfulness（忠实度）、上下文相关度、答案相关性。运行前须已有入库资料；评估不自动上传文档、不增加公开 HTTP 路由，也不改变正常 `/search`、`/answers` 的响应或阈值。评估结果不构成医学正确性证明。

## 评测数据与命令

- JSONL 每行一题，字段为非空 `question`、非空且不重复的 `relevant_chunk_ids`（字符串数组），可选唯一 `id`；未提供时用稳定的行号标识。相关性是人工标注的二元块相关性，必须对应当前已入库的块 ID。运行前可通过 `/search` 查看候选块 ID，并人工核对原文与相关性。文档替换后块 ID 可能改变，须同步更新题集。
- 命令 `python -m medical_rag.evaluate --dataset <path> --output <path> --top-k 5 --answer-provider deepseek --judge-provider qwen`。参数允许选择现有两个 provider，`top-k` 限定 1–20；默认输入按 UTF-8 解码。输出 JSON 包含配置（不含密钥）、逐题结果和汇总；仅在全部题目校验通过后运行评审。输出文件显式覆盖，文档警告可能包含问题、答案、上下文与评审理由，不存入仓库。
- 启动使用与应用相同的 Settings、MilvusStore、Embedder、Reranker、GroundedGenerator 构造；须配置所选答案模型和评审模型的 API Key，两个角色可以选相同 provider，但在报告中披露可能存在自评偏差。模型调用按题顺序进行，不并发；提供评估前的费用提示文档，调用仍由用户显式执行命令触发。

## 检索指标

针对每题，使用现有 `RagService.search(question, top_k)` 的最终证据列表（含重排门槛）。按返回顺序去重块 ID；题集相关块集合记为 R，检索结果记为 P，命中数 h；`precision = h / len(P)`（P 为空时为 0），`recall = h / len(R)`，`F1 = 2PR/(P+R)`（分母为 0 时为 0）。`AP@k = sum(precision@i * rel_i) / min(len(R), k)`，未命中时为 0；`RR@k = 1 / 首个相关块名次`，未命中时为 0。汇总 Precision、Recall、F1 为逐题宏平均，MAP@k 为 AP@k 平均，MRR@k 为 RR@k 平均；不使用向量相似度或答案字符串匹配代替人工相关性标签。所有指标在 0–1 内。报告明确 `k`、返回数量和命中块 ID，避免将它们误读为完整候选集上的分数。

## 模型评审

- `Judge` 是独立于计算指标的可注入组件，使用现有 OpenAI 兼容传输层对应 provider 的模型配置。发送给模型的题目和证据视为不可信数据，要求仅输出严格 JSON 数字分数及简短理由；运行端检查类型、字段和 0–1 范围，拒绝非有限数、缺字段或额外无法识别的响应，不静默纠正分数。
- faithfulness：对非拒答答案中可验证的事实性内容，判断它是否能由本次检索证据支持；0 为没有支持，1 为全部受支持。程序化引文校验不是该分数的替代。
- 上下文相关度：以问题和每条实际返回证据文本判断其对回答问题的帮助程度，逐块评分后取平均；无证据时为 `null`。答案相关性：以问题及生成答案判断是否直接、充分回应问题；不是与某个标准答案的字面相似度。
- 对拒答题目，这三项一律为 `null`，仍保留检索指标；无证据与拒答原因保留在逐题结果。评审理由、原始有效分数及模型标识逐题保存。每个维度单独请求，单项失败只令该项为 `null` 并记录明确错误，不填 0；答案生成失败也记录错误，其语义分数为 `null`，不掩盖检索指标。
- 汇总语义维度时只平均有有效分数的题；如果没有有效分数，汇总为 `null` 并输出有效题数。汇总拒答数／率、评审失败数；上下文相关度逐题先对返回块平均，再跨题平均。理由与分数均可能受模型、提示词、顺序和版本影响，不能称为客观金标准。

## 模块边界与错误处理

- `evaluation_metrics.py`：纯函数，验证排名计算逐题检索指标、汇总宏平均；不访问外部系统。
- `evaluation_judge.py`：评审提示词、响应解析与模型适配；注入 transport 供测试替身使用。
- `evaluation.py`：严格读取及校验 JSONL，依次调用现有服务、指标和评审器，生成结构化报告。
- `evaluate.py`：命令行解析、复用应用组件初始化、JSON 报告输出及明确的非零退出码。
- 输入格式／参数错误应在模型调用前失败，不输出误导性“成功”报告；单题运行时的检索失败记录该题错误，其他题继续。文件读写或初始化失败以非零状态退出。密钥及请求头绝不写入结果或日志，错误信息避免带出服务端原始响应中的敏感数据。

## 测试与验收

- 先做离线端到端评测测试（注入假的服务和评审 transport），再覆盖排名、空返回、部分命中、重复 ID、多个相关块、AP 分母、拒答、单项评审失败、模型输出越界／非数字／非有限值和题集校验。测试默认不访问 Milvus 或收费模型，新增功能须有测试，项目覆盖率目标高于 80%。
- README 给出最小 JSONL 示例、运行命令、各指标的确切分母、输出示例、数据版本／成本／自评偏差和医疗使用边界；`.gitignore` 排除本地题集／结果仅在不会误排用户现有资料的精确路径下配置。
