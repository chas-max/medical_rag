# 医疗 RAG 召回率/精确率异常诊断报告

> 对象：`medical-answer-v10`（v1）在 `medical-health-v2`（150 题 = 120 可回答 + 30 拒答）上的 150 题 GPU 评测，
> 以及 120 道可回答题的**逐阶段检索快照**（`outputs/diag/capture-v10.jsonl`，真实 Milvus + BGE 模型）。
> 所有数字都能用第 6 节的命令复现；实验脚本在 `outputs/diag/`。

## 0. 结论速览

1. **你看到的"50–60"是 child-chunk `Recall@8`（0.538）**；`Precision@8` 是 0.350（上限 0.549）。
2. **当前口径下 Recall@8 的数学上限只有 0.863**：每题标注 4.40 条块，而 `top_k=8` + `max_per_parent=1`
   只能命中每个父窗口的 1 个子块。**不先改口径/预算，90% 无论如何都到不了。**
3. **候选召回不是瓶颈**：多查询 + RRF 融合后的候选池已包含 **91.9%** 的标注块；
   **35 个百分点丢在"重排选 8 条"这一步**（0.919 → 0.569），门控再丢 2.6 个点。
4. 具体缺陷：`max_per_parent=1` 与生成层"按父块去重"逻辑**互相打架**（砍掉兄弟块不省 token，只丢召回）；
   跨主题/多指南对比题（20 题，占 17%）Recall 只有 0.227；v10 门控在 41/150 题上把证据剪到 8 条以下。
5. 修复后（`medical-answer-v11`：`top_k=16`、`max_per_parent=0`、门控只保留校准阈值）：
   **Recall@16 0.538 → 0.723（+18.5pp / +30%）**，Core-Recall 0.621 → 0.794，父窗口召回 0.726 → 0.805，
   nDCG 0.572 → 0.657；端到端子集忠实度 0.93，与 v10 持平。
6. **90% 的两条现实路径**见第 4 节：① 把评测口径改成父窗口/引文覆盖（现在 0.805，上限 0.814 已在
   `k=16, cap=1` 触到）；② 修标注 + 更强重排（候选池天花板 0.919，纯调参到不了 0.90）。

### 1.2 "精确率"也要按上限读

`Precision@k = hits/k`，而每题只有 4.4 条正例 → **k=8 时精度上限 = 4.4/8 = 0.549**。
实测 0.350 = 上限的 64%。"精确率 50–60"在任何 k≥8 的设定下都触不到 90%：
它是**多正例 + 固定 k** 的口径问题，不是排序问题。多正例题应看 `nDCG / MAP / R-Precision`。

## 2. 根因（按影响排序，全部有数据）

### 根因 1：口径与检索预算不自洽 —— 上限被锁在 0.863

| 配置 | Recall@k 上限 |
|---|---:|
| **k=8, max_per_parent=1（现状）** | **0.863** |
| k=8, max_per_parent=0 | 0.999 |
| k=12, max_per_parent=0 | 1.000 |
| k=12, max_per_parent=2 | 0.992 |

推导：标注块平均落在 3.8 个父窗口，4.40 条块里约 1.16 条/父窗口是兄弟块。
`max_per_parent=1` 每个父窗口只放 1 条，兄弟块被结构性排除 → 8 个位置最多覆盖 8 个父窗口的
"每窗 1 条"，达不到 4.40 条中的兄弟部分。**这意味着在现状配置下，"90%"从一开始就不可能**；
而实测 0.538 只用到上限的 **62.4%**，说明排序本身还有 36pp 的差距。

### 根因 2：候选池 91.9%，重排选择只剩 56.9% —— 主矛盾（-35pp）

120 道可回答题的逐阶段快照（生产节点原样回放）：

| 阶段 | 候选池 | 标注块召回 |
|---|---:|---:|
| `retrieval.multi`（主问+子问 × dense+BM25 → RRF） | 161.3 | **0.919** |
| `retrieval.rrf`（+HyDE） | 161.8 | 0.919 |
| `retrieval.rerank`（交叉编码器选 8 条） | 7.3 | **0.569** |
| `evidence.gate`（0.5 阈值 + 0.62 相对下限） | 7.2 | 0.543 |

- 标注块在 RRF 候选池里的名次：中位数 7，P75=21，P90=59；只有 5% 落在 `rerank_k=90` 之外。
- 也就是说：**"找得到"但"排不上去"**。一次选择丢掉 35 个百分点，这是全部改进空间所在。
- 进一步拆分 8 个证据位：平均命中 2.22 条；非命中位中 **56.4% 是"同一份指南、相邻但非标注的父窗口"** ——
  交叉编码器把同文档相邻段落排成近似平局，标注块被挤出前 8。

### 根因 3：`max_per_parent=1` 与生成层的父块去重互相打架（纯亏）

`generation._evidence_payload()` 已经把同一 `parent_id` 的多个子块合并成**一条** prompt 记录，
并在 `chunk_ids` 里列出全部兄弟 id（这些 id 本来就可以被引用）。所以：
- 多带兄弟子块**不增加 prompt token**；
- 兄弟 id 本来就是合法引用锚点。

而重排层在选证据时按父窗口只留 1 条 → 只损失 child 召回与可引用 id，**一点上下文都没省**。
把上限放开（`max_per_parent=0`）在 k=8 就带来 **+5.1pp**（0.557 → 0.609），是零成本的。

### 根因 4：跨主题/多指南对比题系统性失守（20 题，占 17%）

| 类别 | n | Recall@8 | Hit@8 |
|---|---:|---:|---:|
| **跨主题综合与多版本对比** | 20 | **0.227** | 0.750 |
| 心血管诊疗与食养 | 16 | 0.451 | 1.000 |
| 内分泌代谢与体重管理 | 20 | 0.530 | 1.000 |
| 呼吸、传染病与儿科 | 14 | 0.744 | 1.000 |

6 道 0 命中题里 5 道属于该类别。逐题回放（MHE2-0131）显示：
系统**已经覆盖了 3–4 份正确指南**，但 8 条证据全落在"概述/相近章节"，没有一条落在标注页；
而交叉编码器排第 1、2 的块（"5.3.2 调脂治疗…降压联合调脂…LDL-C"）在语义上比标注的
"八段锦/中医综合调理"更贴题——**这一类题的标注本身偏松/偏页**（见 4.3），
排序再好也拿不到分；同时缺"按来源/按事实点"的覆盖配额。

### 根因 5：v10 门控用召回换精确率（41/150 题被剪到 8 条以下）

- v9→v10：Precision 0.284→0.350，Recall 0.553→0.538。
- `evidence.gate.relative_floor_ratio=0.62` 在 **41/150** 题上剪掉尾部证据（v10 平均证据数 6.73，v9 恒为 8）。
- `retrieval.rerank.threshold=0.5` 还会直接丢弃 <0.5 的候选：部分 grade=1 标注块在 0.4–0.5 被丢弃。
- 把相对下限关掉（只保留 0.5 校准阈值）在 k=16 上多拿 **+1.7pp**（0.705 → 0.723），门控阈值本身没动；
  但"证据变多"会让个别拒答题变得可作答（见 3.3 的安全回归提醒）。

## 4. 为什么"90%"现在到不了，以及两条到达路径

### 4.1 硬约束

- k=8 + cap=1：**上限 0.863**（离 90% 差 3.7pp，且在现状配置下不可突破）；
- 候选池（不截断）天花板：**0.919**（9.1% 的标注块根本不在池里，涉及 34 道题）；
- 实测 0.723 = 候选池天花板的 79%；剩余约 20pp 由交叉编码器排序误差 + 标注噪声共同构成；
- 父窗口口径的上限同理：`k=16, cap=1` 已经到 0.814，再往上同样受排序与标注限制。

### 4.2 路径 A（推荐，1–2 天）：口径与预算对齐，把父窗口召回做到 0.81+

1. `top_k` 提到 16（已做，child Recall 0.723）；
2. **把主指标换成 Parent-Recall / 引文覆盖率**：生成层实际喂给模型的是 `parent_text`，
   在同一份回放里 `k=16, cap=1` 已经拿到 **0.814**（比现状 +6.6pp），配 `nDCG@k`、`R-Precision` 一起报；
   注意 `cap=1` 的 child 召回只有 0.630 —— **两种口径要分开选配置**，不要混着看；
3. 评测 harness 的 `TOP_K` 必须与工作流 `top_k` 一致（v10 是 8 vs 8；v11 之后要 16 vs 16，
   否则前 16 条只按前 8 条打分，收益被截断一半）；
4. 对比题加"每份被点名指南至少 1 条"的来源配额（`subquery_quota` 已有骨架，需按 `source_id` 扩一档），
   目标把 20 道对比题从 0.227 拉到 0.5+（整体约 **+4~6pp**）。

### 4.3 路径 B（2–3 天）：修标注 + 更强重排，冲 child-level 0.85–0.90

1. **标注审计（收益最大）**：跨主题 20 题逐题复核 `source_refs`。MHE2-0131 的 5 条标注中，
   至少 2 条与问题问的"降脂靶点/升级顺序/中西医定位"不对位，而有 1 条标注块**不在候选池**；
   这类题共 20 道（占 17%，Recall 0.227），修好后整体约 **+6pp**。
2. **重排增强**：对候选池 top-30 做 LLM listwise 重排（或 bge-m3 + SPLADE 混合召回），
   目标把 0.723 → 0.80+；代价是 +1–2s/题。
3. **按事实点分解**：对比题现在只按"指南"切子问，改成"事实点 × 指南"分解（`enable_llm_decompose`
   对这类题不触发），子问配额 1→2。

### 4.4 标注质量究竟占多少？（实测，`outputs/diag/label_quality.py`、`quote_recall.py`、`grade_effect.py`）

结论：**标注口径/噪声能解释约 8–13pp 的召回缺口（占 46pp 缺口的 20–25%），不是主因。**

支持"标注有问题"的三组数字：

| 现象 | 数字 | 对召回的影响 |
|---|---|---|
| 一个 quote 映射到多个 chunk（`containment_multi` / `parent_containment_multi`，29 题） | 这些题 child 召回 0.441，**quote 口径 0.550** | 整体 0.538 → **0.590（+5.2pp）** |
| 35% 标注是 grade-1"补充证据" | grade-2 命中率 0.574，**grade-1 只有 0.375**；只看 core 时 0.621 | **+8.3pp** |
| 跨主题对比题 gold 最弱 | 裁判给 gold 0.420（全类目最低），2/14 题未标注证据 ≥ gold | 该类 quote 口径也只有 0.261 |

反证（说明不是"标注漏了一堆同样好的块"）：

- 同一份检索列表内，裁判给 **gold 0.539 / 未标注 0.267**；只有 **17%** 的未标注块达到该题 gold 均值；
  103 题里只有 **8 题**出现"未标注平均 ≥ gold 平均"，34 道低召回题里只有 **3 道**。
- 交叉编码器：选中的 gold 0.922 vs 选中的未标注 0.883（很接近，说明顶部竞争激烈），
  但**未选中的 gold 只有 0.692** —— 被漏掉的 gold 本身就偏弱，主要是 grade-1 补充证据。
- 裁判对全部 8 条证据的均值 0.370，与"gold 块 0.539 / 未标注 0.267"的加权结果 0.350 一致：
  低精确率（0.350）不是标注把好东西判没了，而是检索结果里确实有 2/3 是弱相关。

⚠️ 局限：裁判是 qwen3.8-flash，只看得到当次检索列表（看不到全库未标注块），绝对分有压缩。
要把 8–13pp 的估计变成实测，唯一的办法是 **pooled 重判**：对每题 top-20 候选（含未标注）做
0–2 级相关性判定，再重算 recall/precision —— 约 120×20=2400 次判定，qwen-flash 约 20–30 分钟。

## 5. 附带的两个工程问题

1. **运行时 `top_k` 被工作流配置静默覆盖**：`retrieval.rerank` 取 `config["top_k"]` 优先于入参，
   所以 `POST /answers {"top_k": 5}` 不生效。建议改成入参优先，或至少在 API 文档中标注。
2. **默认评测 k 与题集设计矛盾**：题库按"3–6+ 条 source_refs"设计（README 明确写了要避免
   "Precision@k 上限锁死"），但 harness 用 `TOP_K=8`，恰好把 P@8 锁死在 0.55、R@8 锁死在 0.86。
   这是 v2 题库上线时遗漏的口径回归。
