# 提示词：分支化 RAG 路由与异质优化

> 用途：把「按问题类别路由 + 分支专用修复 + 全局缺陷全局修」这套设计主张，交给架构师/实现者执行。

---

## 一、你的观点（归纳）

1. **路由不是目的，是分配专用修复的手段。** 不应指望「路由本身」提升指标，而应把路由当成分流机制：不同类别的问题走不同分支，每个分支针对**该类问题的具体失败模式**做定制优化。
2. **拒绝一刀切全局优化。** 如果把针对难题（跨主题）的强化配置（更大 top_k、扩展召回等）套用到所有检索，那么简单问题也会付出同样的成本与延迟——这在工程上不可接受。
3. **类别缺陷是异质的，所以修复必须异质。** 安全型缺陷、生成型缺陷、检索型缺陷不能共用同一套手段。
4. **只有真正的全局缺陷才做全局修复。** 判断标准是：该缺陷是否跨越所有类别发生。若是，才值得全局改；否则应下沉到对应分支。
5. **先量化，再设计。** 任何方案在动手前必须先判断性能提升幅度；幅度不足则不应实施。

## 二、提示词（可直接使用）

设计并实现一套「问题类别路由 + 每个分支专用优化 + 全局缺陷全局修复」的执行架构，提升 RAG 端到端质量，同时**不得**让简单问题承担难题的检索成本。

# 核心设计主张（必须遵守，不可简化）

1. 路由只是分流机制，本身不产生指标收益。它的价值在于：每个分支可以携带针对该类问题失败模式的专用修复。
2. 禁止把面向难题的强化配置（大 top_k、同页扩展、多轮检索等）全局套用。每类问题的检索预算必须与其难度匹配。

4. 仅当某缺陷跨越所有类别发生时，才允许做全局修复；否则必须下沉到对应分支。
5. 先量化后实现。若某分支的预期收益经量化后不足，不要实现它。

## 三、这段提示词的用意

- **把「路由」从目标降级为机制**：避免执行方又去优化「路由准确率」或「换管线找召回」，那是已被证伪的方向。
- **用成本前沿锁死预算**：+58% / +60% 的硬指标，直接回应「不能让所有检索都变贵」。
- **把两类缺陷分开处理**：88/150 题的数值删除、corrective 替换式重排属于全局；scenario 安全与 numeric 生成属于分支。
- **明确标注待验证项**：scenario 充分性校验和 numeric 数值修复尚未端到端实测，提示词要求执行方标注假设而非当作既成事实。
